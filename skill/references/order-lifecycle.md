# 工具与订单状态

工具名、参数及返回字段以本次连接器 schema 为准。历史示例不能代替当前契约。工具缺失、结构未知时说明缺口，不能自造编码、订单或链接。

到店链路：门店 → 菜单 → 必要的套餐详情／券 → 试算 → 报价 → 用户确认 → 同配置复验 → 创建一次 → 查询状态。

| 状态 | 允许动作与停止条件 |
|---|---|
| 缺地点／取餐方式 | 只读查询和澄清，不下单 |
| 有菜单未试算 | 构造候选，不报确定实付 |
| 已报价待确认 | 修改或等待，不创建订单 |
| 已确认 | 复验完全一致后创建一次；变化须重新确认 |
| 创建超时／断连 | 查已知订单，必要时用 `order-list` 核对近期订单；不盲目重试 |
| 创建结果不明、无法查询 | 告知可能已创建，引导官方渠道核实；停止创建 |
| 待支付 | 展示同一支付入口，按用户要求查状态或取消；二维码失败不重下 |
| 已支付 | 查询后反馈取餐信息，不再发过期支付入口 |
| 已取消／过期 | 说明状态；用户仍要餐则重新报价与确认，不自动重下 |

用户重复说“下单”，已有未支付／未知订单先核实，不当成第二份订单。取消只在用户明确要求且目标已识别时执行，失败不声称成功。

## 异常

- **401**：停止调用，引导本地更新 Token，不索取聊天密钥。
- **429**：遵循服务重试间隔，只读请求最多重试一次；无间隔或再次失败说明稍后重试。
- **菜单／试算失败**：核对门店、时段、商品选项、资格，修复失败候选一次；不能验价就不下单。
- **创建超时**：先核实状态，无法排除已创建就停止；没有幂等保证时重发会产生重复订单。
- **二维码失败**：保留订单，提供同一链接；不上传到第三方二维码服务。
- **支付未知**：明确尚未确认，以 `query-order` 或官方结果为准。

## 支付展示

`payH5Url` 仅从当前订单取得，检查为 HTTPS 绝对链接；异常来源先核实。脚本只检查格式，不证明域名归属。金额、订单号、截止时间用工具原值，不补“通常 15 分钟”。

安装 `requirements.txt` 后，经 stdin 给 `pay_qr.py --url-stdin` 传链接，可用 `--expires` 传真实截止时间。真实链接不能进入公开日志、演示、第三方二维码 API。支持内联 SVG 就渲染，否则使用宿主支持的附件或原始链接。
